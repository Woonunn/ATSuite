## 验证边界

这是 PoC 实现和有明确限制的实验结果，**没有完成新的受控混合云扩缩容实验，也没有完整实际账单收益证明**。
解析费率有日期、地区、计费单位及来源；预测需求、按实测资源重计的费用、供应商计量的可归属计算费用估算、实际账单严格分开。
缺失计量不会填零后声明完整费用。共享资源按池/时间窗口计费一次，不能与完整窗口账单再次累加。

## E1-B 独立任务留出

使用既有 `cloud-fixed-typical-envref-v3/formal` 的 764 次请求、6 个不同任务。
每次将一个任务完全从初始训练排除；对比 0/3/20 个初始样本及冻结/在线反馈。
冻结留出不会摄入测试任务结果；在线版本仅在完成且可见后更新。原始来源哈希与配置哈希保存在 summary。

所有设置下历史 shadow 请求均能完成选择；这使用明确声明的虚拟容量，**不是未知真实云容量下的准入成功率**。
历史记录是独立 Provider 运行，不能把选中的历史延迟冒充混合路由下的新队列/延迟。
下表是各真实历史执行池的预测平均延迟绝对误差（秒），每 Provider 20 个初始样本：

| 留出任务 | 冻结 MAE | 在线反馈 MAE |
|---|---:|---:|
| csv_excel_29 | 5.99 | 4.90 |
| csv_excel_34 | 25.71 | 4.84 |
| human_12 | 7.63 | 7.95 |
| human_142 | 18.82 | 6.90 |
| human_15 | 5.05 | 3.46 |
| human_7 | 149.90 | 76.02 |

反馈并非单调改善；较重任务仍有明显误差。AgentCore 的实际 CPU/内存计量缺失，完整解析输入覆盖不足时继续回退，不能用 requested 资源冒充实际分配。

## E1-A 可归属计算费用

复用 2,888 次请求及延迟到达的供应商计量修订。按到达时间、Provider、请求 ID 的固定顺序每 10 个请求评分一次，共 289 个，抽样不依赖完成时间或结果。
所有可见历史证据仍参与更新；固定 Capture 的同一资源画像去重，不把重复画像当成新类型。
状态逻辑量缺失阻止完整基础设施费用比较，但能够比较有完整输入的 CPU/内存/调用等子项。
比较只包含供应商计量估算中实际存在的同名费用子项，避免把额外磁盘或状态费用混入参考分母。

WAPE = 总绝对误差 / 总参考费用。以下是 **供应商计量重计的计算费用估算误差**，不是总账单误差：

| Provider / 更新方式 | 独立评分请求数 | WAPE |
|---|---:|---:|
| aws_lambda / frozen | 72 | 4.82% |
| ali_fc / frozen | 71 | 10.14% |
| aws_lambda / adaptive | 72 | 11.15% |
| ali_fc / adaptive | 71 | 11.67% |

这组数据中在线校准的计算费用误差高于冻结模型，尚不能证明平台校准随观测增加而改善。
工具运行时计数器包含状态恢复/同步；平台校准先扣除已测同步，再加预测同步，避免重复计费。
只有预测值、没有同任务历史价格也可计算；计量修订必须在 `available_ns < decision_ns` 后才参与校准。

## 联合路由和容量机制实验

使用现有 Tool 级离散事件 simulator；三类工作负载分别改变计算、状态及 LLM idle，负载包含低谷和突发。
训练/验证服务样本使用分离的来源 ID，但都是**合成数据**，只验证控制与计费机制。
比较静态、仅路由、独立扩缩容及不同权重的联合优化。所有准入请求完成，无未覆盖服务区间。
